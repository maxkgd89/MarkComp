# Markdown Review Studio

A local desktop app for reviewing and revising large Markdown documents. It shows a structure tree, a read-only original, an editable revision, word-level diff highlighting, GitHub-style split/unified diff, and synchronized scrolling.

## Requirements

- Node.js 22+
- Windows (developed on Windows 11)

## Run

```powershell
npm install
npm run dev
```

## Production-style run

```powershell
npm run build
npm run preview
```

## Windows executable

```powershell
npm run dist
```

This builds the app and packages it with electron-builder. Artifacts land in `dist/`:

- `Markdown Review Studio-Setup-0.1.0.exe` — NSIS installer with desktop and Start-menu shortcuts. Pick "Only for me" to install without admin rights.
- `Markdown Review Studio-0.1.0-portable.exe` — single-file portable app; data is kept in a `userdata/` folder beside the executable.

`npm run pack` produces an unpacked app in `dist/win-unpacked/` for quick checks, and
`npm run dist:portable` builds only the portable executable.

The icon is `build/icon.ico`, generated by `build/make-icon.ps1` (regenerate with
`powershell -ExecutionPolicy Bypass -File build/make-icon.ps1`).

### How the build is assembled

- `npm run launcher` compiles `build/launcher.cs` into `build/launcher.exe` with the
  .NET Framework compiler that ships with Windows.
- `build/after-pack.cjs` renames the packaged Electron executable to
  `Markdown Review Studio Core.exe` and puts the launcher in its place as
  `Markdown Review Studio.exe`.
- The launcher starts the app normally, and if Chromium's sandbox cannot initialize
  (the process exits with `STATUS_BREAKPOINT` / `0xC0000005` before any app code runs,
  as happens on this machine) it retries once with `--no-sandbox`. It also waits for the
  app to close, which keeps the portable launcher's temporary folder alive.

Notes:

- The executables are unsigned, so Windows SmartScreen may warn on first launch.
- Installed builds keep app data in a `userdata/` folder beside the executable when writable, otherwise in `%APPDATA%\markdown-review-studio`.
- Configuration lives in `electron-builder.yml`; `node_modules` is not packaged because
  electron-vite bundles the renderer and main process.

### Troubleshooting

- If setup reports "Setup was not completed successfully", choose "Anyone who uses this
  computer" and approve the elevation prompt, or use the portable executable instead.
- If the app still exits immediately, run the executable from a terminal with
  `--no-sandbox` (the portable executable forwards its arguments to the app).

## Notes

- `npm install` must include dev dependencies. If `NODE_ENV=production` is set in your shell, run `npm install --include=dev`.
- The `dev`/`preview` scripts pass `--noSandbox` because Chromium's sandbox crashes in this environment. In development, user data is stored in `.userdata/` inside the project (gitignored); packaged builds use the locations listed under **Windows executable**.

## Features

- Open a Markdown file, or load the bundled sample.
- Structure tree (H1–H6) with branch collapse and heading navigation.
- Section folding: gutter chevrons plus Fold all / Unfold all.
- Editable revision that never modifies the original.
- Save revision / Save as (the original path is never a save target).
- Side-by-side diff with added/removed/modified highlighting and word-level changes.
- Dedicated GitHub-style diff: split and unified modes, with Change navigation.
- Synchronized scrolling with an on/off toggle.

## Test fixtures

- `samples/sample.md` — small document with H1–H4 structure.
- `samples/large.md` — 10 topics, 49 headings, all Markdown element types.
- `samples/chatgpt-style.md` — bold pseudo-headings that must not become tree nodes.
- `samples/edge-cases.md` — skipped heading levels and out-of-order sections.

## Markdown parsing

The parser is local and deterministic: ATX and setext headings, CRLF/LF, Unicode/emoji, inline formatting, links and code in headings, closing `#` sequences, fenced/indented code protection, and `<think>` reasoning blocks. Diagnostics (skipped levels, duplicates, missing H1, unclosed fences, ambiguous `#Heading` lines) are reported without rewriting the document. Original/revision headings are matched by stable id, text, structural path, and section similarity, so renames keep their correspondence and deleted sections are marked unmatched.
